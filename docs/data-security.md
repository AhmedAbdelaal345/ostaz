# نموذج البيانات والصلاحيات في أستاذي

## المبدأ العام

كل عملية على بيانات التطبيق تمر عبر `protectedProcedure`، لذلك لا تُنفذ إجراءات المجموعات والطلاب والملف الشخصي إلا بعد وجود جلسة مستخدم صالحة. يمرر الخادم `ctx.user.id` إلى كل helper في `server/db.ts`، ويُستخدم هذا المعرّف في شرط القراءة والتعديل والحذف.

## الجداول

| الجدول | الغرض | مفتاح العزل |
|---|---|---|
| `users` | هوية المستخدم القادمة من Manus OAuth | `id` و`openId` |
| `teacher_profiles` | بيانات المعلم والدفع والتواصل والقالب والوضع | `userId` فريد |
| `study_groups` | المجموعات ومواعيدها ورسومها | `userId` |
| `students` | الطلاب وحالة الدفع وربط المجموعة | `userId` |

## الإجراءات المحمية

توجد إجراءات `bootstrap` و`profile.get/save` وعمليات `groups.list/create/update/delete` و`students.list/create/update/delete` في `server/routers.ts`. لا تُستخدم مدخلات العميل لتحديد المالك؛ المالك يُستخرج دائمًا من جلسة الخادم، كما أن كل تحديث وحذف يستخدم شرطَي `id` و`userId` معًا.

## حدود التكاملات

بيانات البطاقة أو مفاتيح الدفع لا تُخزن في قاعدة بيانات التطبيق. عند تفعيل Stripe مستقبلًا، يُحفظ فقط المعرّف الضروري للاشتراك أو العميل، بينما تُدار بيانات البطاقة داخل مزود الدفع. إشعارات المتصفح الحالية تطلب إذن الجهاز، أما Push الخلفية الكامل فيحتاج مفاتيح VAPID وتسجيل اشتراك Push خادمي.
